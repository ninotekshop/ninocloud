Cấu trúc cơ sở dữ liệu (Database Schema) cho hệ thống POS F\&B **Ninotek** được thiết kế theo chuẩn quan hệ (Relational Schema), tối ưu cho mô hình **Hybrid Offline-First** (SQLite/PostgreSQL tại máy trạm **NinoPOS**) và đồng bộ lên **Cloud PostgreSQL**.  
**1\. Sơ Đồ Bảng & Mối Quan Hệ Cốt Lõi**

\[Categories\] ──\< \[Items\] ──\< \[Recipe\_Items\] \>── \[Ingredients\]  
                   │  
                   ├──\< \[Order\_Details\] \>── \[Orders\] ──\> \[Tables\] ──\> \[Areas\]  
                   │                            │  
                   └──\< \[Item\_Toppings\]         ├──\> \[Users\] (Employees)  
                                                └──\> \[Payments\]

**2\. Chi Tiết Khóa & Trường Dữ Liệu (Data Tables)**  
**A. Nhóm Quản Lý Khu Vực & Bàn (Tables & Areas)**

* areas (Khu vực):  
  * id (UUID/INT, PK): Mã khu vực.  
  * name (VARCHAR): Tên khu vực (Tầng 1, Sân vườn, VIP...).  
  * sort\_order (INT): Thứ tự hiển thị.  
* tables (Danh sách bàn):  
  * id (UUID/INT, PK): Mã bàn.  
  * area\_id (FK ➔ areas.id): Thuộc khu vực nào.  
  * name (VARCHAR): Tên/Số bàn (Bàn 01, Bàn 02...).  
  * status (ENUM): EMPTY (Trống), OCCUPIED (Có khách), RESERVED (Đã đặt).  
  * current\_order\_id (UUID, Nullable): ID của đơn hàng đang phục vụ tại bàn.

**B. Nhóm Quản Lý Menu & Định Lượng (Menu & Recipes)**

* categories (Danh mục món):  
  * id (INT, PK), name (VARCHAR), color\_code (VARCHAR).  
* items (Thực đơn / Món ăn):  
  * id (UUID/INT, PK), category\_id (FK ➔ categories.id).  
  * name (VARCHAR): Tên món.  
  * base\_price (DECIMAL): Giá bán niêm yết.  
  * unit (VARCHAR): Đơn vị tính (Ly, Dĩa, Chai...).  
  * is\_active (BOOLEAN): Trạng thái kinh doanh.  
* ingredients (Kho nguyên liệu thô):  
  * id (UUID/INT, PK), name (VARCHAR), stock\_quantity (DECIMAL), unit (VARCHAR), min\_stock\_alert (DECIMAL).  
* recipe\_items (Định lượng nguyên liệu cho món):  
  * id (PK), item\_id (FK ➔ items.id), ingredient\_id (FK ➔ ingredients.id).  
  * quantity\_required (DECIMAL): Số lượng nguyên liệu tiêu hao cho 1 đơn vị món (vd: 0.02 kg hạt cafe).

**C. Nhóm Xử Lý Đơn Hàng & Gọi Món (Orders & Kitchen)**

* orders (Đơn hàng / Hóa đơn):  
  * id (UUID, PK): Mã đơn hàng toàn hệ thống.  
  * table\_id (FK ➔ tables.id), user\_id (FK ➔ users.id \- Nhân viên tạo đơn).  
  * order\_type (ENUM): DINE\_IN (Tại bàn), TAKE\_AWAY (Mang về).  
  * status (ENUM): PENDING (Chờ làm), SERVING (Đang ăn), COMPLETED (Đã thanh toán), CANCELLED (Đã hủy).  
  * subtotal (DECIMAL), discount\_amount (DECIMAL), final\_total (DECIMAL).  
  * created\_at (TIMESTAMP), completed\_at (TIMESTAMP).  
* order\_details (Chi tiết món order):  
  * id (UUID, PK), order\_id (FK ➔ orders.id), item\_id (FK ➔ items.id).  
  * quantity (INT): Số lượng món.  
  * price (DECIMAL): Đơn giá tại thời điểm order.  
  * note (TEXT): Ghi chú (Ít đường, không cay...).  
  * kitchen\_status (ENUM): WAITING (Chờ làm), COOKING (Đang chế biến), READY (Đã xong), SERVED (Đã lên bàn).

**D. Nhóm Thanh Toán & Đồng Bộ Cloud (Payments & Sync)**

* payments (Giao dịch thanh toán):  
  * id (UUID, PK), order\_id (FK ➔ orders.id).  
  * payment\_method (ENUM): CASH (Tiền mặt), VIETQR (Chuyển khoản), CARD (Thẻ).  
  * amount (DECIMAL): Số tiền thanh toán.  
  * transaction\_ref (VARCHAR): Mã tham chiếu ngân hàng (cho VietQR).  
  * created\_at (TIMESTAMP).  
* sync\_queue (Hàng đợi đồng bộ Offline ➔ Cloud):  
  * id (BIGINT, PK), entity\_type (VARCHAR \- orders, payments...), entity\_id (UUID), payload (JSONB), status (ENUM \- PENDING, SYNCED, FAILED), updated\_at (TIMESTAMP).

**3\. Chiến Lược Đồng Bộ Cho Hệ Thống Ninotek**

* **Chỉ số UUID v4:** Tất cả các bảng giao dịch (orders, order\_details, payments) dùng chuỗi UUID làm Primary Key để tránh xung đột mã id khi máy POS và app Mobile tạo dữ liệu độc lập offline.  
* **Cơ chế CDC (Change Data Capture):** Bảng sync\_queue lưu vết mọi thay đổi dữ liệu tại máy Windows **NinoPOS**. Khi có mạng Internet, một Worker ẩn sẽ tự động đẩy các bản ghi PENDING lên Cloud Server để **NinoDash** truy xuất báo cáo ngay lập tức.
